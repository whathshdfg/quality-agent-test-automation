# Quality Agent Studio：需求驱动的智能测试工作台

> Atoms-Demo 笔试项目说明

## 项目定位

Quality Agent Studio 是一个需求驱动的应用生成与质量评审工作台。用户输入自然语言需求后，应用生成智能体会生成完整的单页应用代码，经过自动校验与修复后直接运行在隔离预览中。用户可以继续对话修改应用、查看或恢复历史版本，并下载源码。

项目同时保留了 `quality-agent` 的领域特色：将业务需求拆解为规则、测试点和测试用例，分析覆盖缺口并定向补充。这形成了“先生成应用，再从需求角度评审质量”的产品方向。

## 挑战要求对应情况

| 挑战要求 | 当前实现 |
| --- | --- |
| 可运行网页应用 | React + Vite 前端与独立 FastAPI 后端，可使用 Docker 统一部署 |
| 智能体生成应用 | 服务端调用真实 OpenAI 兼容模型，根据需求生成完整 `index.html` |
| 可视化展示 | 代码文件与运行预览并列展示，预览中的表单、筛选和状态操作可以实际使用 |
| 真实交互 | 支持创建应用、追加需求、版本切换、版本恢复、下载源码、测试用例编辑与覆盖补充 |
| 数据持久化 | SQLite 保存项目、对话与代码版本；受控浏览器存储保存生成应用的数据 |
| 初始化和主流程 | 首次创建项目后自动生成，展示实际阶段、错误和重试入口 |
| 延展能力 | 提供需求规则、测试点、测试用例及覆盖缺口分析 |
| 在线访问 | 部署配置已提供；公网地址在部署完成后填写到本文末尾 |

## 核心流程

```text
输入应用需求
  → 分析需求与当前版本
  → 模型生成结构化文件
  → 校验 JSON、HTML 和安全边界
  → 必要时自动修复（最多两次）
  → SQLite 保存新版本
  → iframe 隔离运行
  → 继续对话修改或恢复旧版本
```

界面只展示真实执行阶段与校验错误，不展示模型内部思考过程。生成失败后，项目会保存失败状态和错误信息，用户可以直接重试。

## 已完成功能

### 应用生成工作区

- 三栏界面：需求对话、生成源码、运行预览。
- 创建项目时输入名称与完整应用需求。
- 使用真实模型生成内联 HTML、CSS 和 JavaScript。
- 通过 SSE 返回需求分析、代码生成、结构校验和自动修复阶段。
- 追加自然语言需求时，结合原始需求和当前代码生成新版本。
- 查看任意历史版本，将旧版本恢复为新的当前版本。
- 下载当前 HTML 源码。
- SQLite 保存项目、对话和全部版本，服务重启后可恢复。

### 隔离预览与应用数据

- 预览 iframe 只启用 `allow-scripts`，不启用 `allow-same-origin`。
- 内容安全策略禁用外部网络、远程脚本、表单提交、插件和嵌套页面。
- 服务端拒绝网络请求、宿主窗口访问、Cookie、外部资源和直接 Web Storage 等危险代码模式。
- 生成应用通过受控 `postMessage` 接口读写数据，宿主校验消息来源、项目 ID、键名及容量。
- 不同生成项目使用独立存储空间，刷新预览后数据仍可恢复。

### 质量工作台

- 将业务需求拆解为规则和分层测试点。
- 生成并编辑测试用例，支持搜索、筛选、复制、删除和执行状态标记。
- 计算规则、功能、参数和风险覆盖情况。
- 识别缺失维度，支持单项补充和一键补齐。
- 使用浏览器 localStorage 保存质量任务。
- 导出 Markdown 报告和 JSON 数据。

覆盖率表示规则模型中的资产关联情况，不等同于代码覆盖率或真实测试通过率。执行状态由用户记录，不代表系统已经运行真实接口测试。

## 实现思路与关键取舍

### 单文件应用作为第一阶段边界

当前生成物限定为一个不超过 300 KB 的 `index.html`，不安装 npm 包，也不执行生成的 Shell 或服务端代码。这使生成结果可以直接验证和预览，并将执行风险控制在清晰范围内。

代价是无法生成需要后端、数据库或第三方依赖的复杂应用。若继续扩展，应把多文件构建放入一次性容器，并增加 CPU、内存、时间和网络限制。

### 可验证的生成流程

模型必须返回固定 JSON 结构。服务端解析后检查文件数量、路径、必要 HTML 结构、文件体积和禁止能力。校验失败会把明确错误反馈给模型，最多修复两次；仍不合格则保存失败状态，不把代码送入预览。

### 独立模块保护稳定基线

新增后端、前端和部署文件全部位于 `atoms-demo/`。没有修改现有 V1、V2、V3 工作流核心逻辑，也没有改动原 Python 测试。

### SQLite 与浏览器存储分工

项目、对话和代码版本属于服务端资产，保存在 SQLite。生成应用运行在无同源权限的 iframe，自己的业务数据通过宿主存储桥保存在访问者浏览器。该方案适合单实例 Demo；公开协作产品应增加账号、权限和服务端业务数据存储。

## 推荐演示流程

1. 输入“生成一个订单管理应用，支持新增、状态筛选、取消待支付订单和数据保存”。
2. 观察真实的生成、校验或自动修复阶段。
3. 在源码区查看模型生成的 `index.html`。
4. 在预览中新增订单、筛选状态、取消订单，然后刷新预览验证数据仍在。
5. 输入“增加按客户名称搜索，并实时显示结果数量”。
6. 生成新版本后验证搜索可用，同时确认原有功能仍然存在。
7. 切换到旧版本，再执行“恢复此版本”，确认形成新的版本记录。
8. 下载源码，然后进入“质量工作台”体验需求规则和覆盖分析。

## 验证结果

- 真实模型成功生成订单管理应用并保存为 v1。
- 首轮结果因存储方式不符合规则被拦截，自动修复后通过，证明校验链路实际生效。
- 追加客户名称搜索需求后成功生成 v2，保留原有新增、筛选、状态流转、统计和持久化功能。
- 前端 13 项测试通过，独立后端 3 项测试通过，生产构建通过。
- 仓库 Python 测试共 177 项通过，原有测试保持通过，仅有 1 条第三方依赖弃用警告。

## 当前限制与后续优先级

| 优先级 | 后续能力 | 原因 |
| --- | --- | --- |
| P0 | 完成公网部署并用无痕窗口验收 | 提供评审可直接操作的链接，并确认线上模型配置与持久磁盘正常 |
| P1 | 用户账号和项目权限 | 当前公开服务中的项目历史缺少用户隔离 |
| P1 | 异步后台任务和可恢复事件流 | 当前请求会等待模型返回；长任务应支持断线后重新订阅 |
| P1 | 生成应用自动测试 | 对生成页面执行结构、交互和关键业务流程检查，提高修改后的回归可信度 |
| P2 | 多文件 React 应用和容器构建 | 扩展生成能力，同时需要更强的资源与安全隔离 |
| P2 | 将生成应用送入现有质量工作流 | 自动把业务规则、测试点和用例映射到生成应用行为 |

当前没有账号注册、多人协作、真实测试执行、多文件构建和容器级不可信代码执行。生成结果仍需人工评审。
